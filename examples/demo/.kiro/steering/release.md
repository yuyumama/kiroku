# リリースの手順

リリースは月に1回、手で行います。

1. `main` が最新で、未コミットの変更が無いことを確かめます。
2. テストをすべて実行し、通ることを確かめます。
3. `kakeibo/__init__.py` の docstring の下に、バージョンを書きます（例：`__version__ = "1.2.0"`）。
4. 変更点を `CHANGELOG.md` の先頭に書きます。利用者に見える変更だけを書き、内部の整理は書きません。
5. バージョンと同じ名前のタグを付けます（例：`v1.2.0`）。
6. タグを push します。強制的な push はしません。
7. リリース後に、`data/kakeibo.json` の形が変わっていないかを、前の版のファイルを読み込んで確かめます。

## バージョンの決め方

- 記録のファイルの形が変わるとき：1桁目を上げます。
- コマンドや表示が増えるとき：2桁目を上げます。
- 不具合の修正だけのとき：3桁目を上げます。

## 取り消すとき

- タグを消さず、修正した版を新しい番号で出します。
- 記録のファイルを読めなくなる不具合のときは、前の版に戻す手順を `CHANGELOG.md` に書きます。
